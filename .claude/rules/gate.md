# Gate

- Gate = `tools/vflab-run bash tools/gate.sh` (all fvdep builds, checks + tests run on vflab, shared with fvapi; the desktop runs no fvdep build). Iteration = `tools/vflab-run bash tools/fast-gate.sh` (never the claim). Any other command that builds or runs fvdep code → `tools/vflab-run <cmd>`. Contract + predicates: `docs/contracts/U1-foundation.md`.
- Run phase (`tools/gate.sh` `run_stages`, contract U1 G1): after the build phase (`tools`, `lean-build`) every other stage runs at once — at most `FVDEP_GATE_JOBS` (default: the CPU count), their `GATE_WEIGHTS` (each stage's memory peak alone) within `FVDEP_GATE_MEMORY` GiB (default 4/5 of the run's cap) — then `probes`, then `tree-clean`; the fast gate's build-consuming stages likewise after `lean-build`. `tools/vflab-run` forwards `HOME` + `PATH` alone ⇒ a knob goes inside the remote command (`tools/vflab-run bash -c 'FVDEP_GATE_JOBS=1 bash tools/gate.sh'` = one stage at a time; a red that is green there = contention, e.g. a test's timeout: classify it + queue the fix). A stage builds nothing another stage reads: `lean-build` builds every Lake target of both packages (`meta` holds its lists = the lakefiles'), each `tests/*` Lake package belongs to one stage ⇒ a new target a stage builds on its own joins the lakefile + the lists. A new or grown stage → `tools/vflab-run bash tools/gate-measure.sh <stage>` (no other fvdep job on vflab) → its `GATE_WEIGHTS` entry (anon + shmem peak, GiB rounded up) + its `GATE_FIRST` place (over 90 s alone: longest first).
- `tools/vflab-run`: every unit = its own PID namespace (`PrivatePIDs=yes`: flock = PID 1, the job's shell = PID 2, checked before anything runs, else 125) ⇒ no process of a run can signal fvapi's or another job's (a `kill(-1)` included); an orphan's zombie stays until the run ends (flock reaps none). Every unit: `LimitCORE=1` ⇒ a crash never reaches vflab's `core_pattern` pipe (apport, as root; the kernel skips it at exactly 1, 0 still pipes) ⇒ a process never lowers it: ASan runs take `disable_coredump=0` (else ASan sets 0), a planted abort `prlimit --core=1:1`, never `ulimit -c 0`; probe `core-limit`. Exit = the command's status; 2 = a malformed setting (no remote action); 125 = setup, sync or output mapping failed; a signal, OOM kill or timeout never exits 0. `FVDEP_VFLAB_TIMEOUT` = whole seconds (default 7200); `FVDEP_VFLAB_MEMORY` = the unit's MemoryMax, a K/M/G/T size below the slice's cap (default 24G; at or above → 125: an OOM must stay inside the run, never reach fvapi's processes); stderr closes with the unit's accounting line (`vflab-run: Finished with result: …; Memory peak: …`). Workspaces = `~/gate/ws/fvdep-*` alone; `tools/vflab-reclaim.sh` removes orphaned ones.
- `tools/vflab-run` holds one lock per workspace (= per worktree): an ad-hoc command from a worktree whose gate is running queues behind it ⇒ run independent work from another checkout (its own workspace + lock) or after the gate. A command piped into `tail`/`head` returns the pipe's last status ⇒ `bash -c 'set -o pipefail; …'` (else a failed `lake build … | tail` reads rc 0).
- CI gate, once `main`'s CI is green: `bash tools/ci-gate.sh <unit>` (refuses a dirty tree: with work in progress in the worktree, run it from a clean checkout of the commit, e.g. the main checkout after its fast-forward; pushes `ci/<unit>`, green only when every shard job + the CodeQL run succeeded with no open alert on the branch; deletes it when green). CI's jobs: `gate (lean)` + `gate (suites)` (the run phase split, each ≤ 40 min) + `gate (checks)`, then `gate (probes)` on the run shards' green marks (artifact; `marks` refuses a missing or stale one). It runs beside the vflab full gate, never in place of it (adapts Execution's "pool or `CI gate`": both): each unit's commit still takes `tools/vflab-run bash tools/gate.sh`, the one run where `sys-suite`'s `F.filesystem.zfs` executes (CI runners report it SKIP: `.claude/rules/checks.md`). Until `main`'s CI is green the full gate runs on vflab alone.
- Step ledger = `.gate/ledger.tsv` in the run's workspace. Each red classifies on the spot before a rerun counts: `tools/vflab-run bash tools/gate-ledger.sh` lists unclassified reds, `… classify LINE product|gate|flake|planted` sets one, `… summary` = per-stage runs, reds by class + seconds.
- `prototype/fvdep/` stays outside the gate (shell, python, lean-style + imports skip it; `vulns` scans its lockfiles) until U14 retires it; a change reaching it → its `Artifacts` smoke.
