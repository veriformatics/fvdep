# Coverage ledger (contract `docs/contracts/U2-core.md` L1–L9)

- Stage `coverage` (shard `lean`, fast gate too) = `lake build FvdepLedger` + `fvdep-ledger --check ../docs/verification.md` (in `tool/`; the checker loads `FvdepLedger.Rows` at run time + `lake exe` builds the exe's own imports alone ⇒ the rows' build first, else a row edit or plant meets a stale `.olean`): binds each claim about fvdep's own code to a theorem about the executed function on its shipped call path: every owned definition a root's `main` reaches lies in some row's subject closure; each claim = a `Prop` definition in `tool/FvdepLedger/Rows.lean` (`*Claims` namespaces) whose theorem's type equals it as a term (alpha-equivalence; defeq is not enough); axioms ⊆ {propext, Classical.choice, Quot.sound}; `leanchecker` replays every owned module (a `debug.skipKernelTC` forgery passes `#print axioms`).
- Stage `ledger-suite` (shard `lean`, fast gate too) = `bash tests/ledger/run.sh`: cases in parallel (`FVDEP_LEDGER_JOBS`, default nproc; `FVDEP_LEDGER_ONLY=<id>` = one case). The fast gate reuses a green verdict while its input closure (checker, fixtures, driver, Lake configs, toolchain pins: `ledger_suite_key` in `tools/gate.sh`) is byte-identical; the full gate always runs it.
- `coverage` also holds U6 Q2's profile freeze (`--freeze ../docs/profile-freeze.txt`, `tool/FvdepLedger/Freeze.lean`): the record = `<profileId> <digest>`, the digest over the profile's normative content — every constant of the profile spec modules + `FvdepCore.Profile.Table` + `.Types`, the converter's cap logic (`FvdepIO.Parse.loop`, `capAt`, `convert`), I1's presence read (`presence`, `oleanAt`), `optionsOf`, the recipes (`FvdepCore.Build.consumer`, `library`, `libraryOptions`, `Role.recipe`), `profileId`, the constants they reach inside the profile's modules (by type + value, a `partial def` through its `_unsafe_rec`), the rest by name, + the `ProfileClaims` statements' own terms + the toolchain commit (`Expr.hash`: binder names + docstrings ignored) ⇒ a rule or datum change under the same id → `ledger: profile: freeze: …`. A deliberate change → a new `profileId` + requalification (contract U6 Q2); re-record = `tools/vflab-run bash -c 'cd tool && lake build -q FvdepLedger && lake exe fvdep-ledger --check ../docs/verification.md --freeze-write ../docs/profile-freeze.txt && cat ../docs/profile-freeze.txt'`, the printed line copied into the tree (a file the workspace alone holds dies at the next sync). Probe `coverage-freeze`: a table atom added → `ledger: profile: freeze:`.
- An edit to a row, statement, theorem or any definition inside a covered closure → `bash tools/ledger-doc.sh` regenerates `docs/verification.md` (pretty-printed statements + `Expr.hash` = drift detection); findings print one line each, `ledger: <component|root>: <code>: <detail>`.
- Specs + proofs about shipped code = lean_lib `FvdepAudit` (`tool/FvdepAudit/<Area>/Spec.lean` + `…/Proof/**`; contract U3 A): outside `libs` (a spec module inside a shipped lib defines code no shipped path calls ⇒ finding `module`) + outside `ledger_suite_key` (a proof edit never reruns the ledger suite), inside the replay (root `Fvdep…`). Imported by `FvdepLedger.Rows` alone: `tools/check-imports.sh imports` (probes `imports-audit-shipped`, `imports-audit-test`); a credited theorem's header = the expanded statement, never a claim-name `Prop` constant (the checker compares terms, it never unfolds). Ported proofs meet fvdep's lints (`unnecessarySeqFocus`: `t1 <;> t2` with one goal → `(t1; t2)`) + lean-fmt's import rules (FMT005 byte order, FMT004 no redundant import).
- New theorem → its statement via `tools/ledger-stmts.py` (JSON on stdin, docstring at its top): the theorem header's own text, so it elaborates to the same term under the same `open`s; wrap lines over 100 columns by hand. A pattern lambda `fun (a, b) => …` inside a type creates a per-declaration `match_` constant ⇒ statement ≠ theorem type: write `fun x => … x.1 x.2`.
- One root per shipped executable: `fvdep`'s `main` + `Ledger.extraRoots` (another executable's owned entry, which its root module's one-line `main` calls whole: two top-level `main`s cannot share the ledger's environment). Each root's `main` = `fun a => interpreter (plan a)` exactly, never a row subject; a path starts at a root's `main`. Probes `coverage-extra-root` (a misshapen extra root → its `root` finding) + `coverage-extra-reach` (a definition an extra root alone reaches, outside every row → `uncovered`). An empty path needs `noCaller` = an open Tasks unit (`- [ ] U<n> `), `support` (subject inside the closure of a row with a valid path; whether its claims serve that row = the faithfulness review's call) or `step` (below).
- A sandbox step running source fvdep ships = one `Ledger.steps` entry (`StepSource`, U2 L1: `driver` = the definition writing the program, `embedded` = its `List (Lean.Name × String)` — `lake test` Q4 holds each text = the file —, `call` = the driver's definition naming the generated call, `classes`): the step's reach = the static closure of the call + every instance of the classes the embedded modules declare (not the exact runtime set: the snapshot's function + the generated IO = residue) ⇒ a definition the step newly reaches outside every row's subject closure = `uncovered`; a step-only subject = `noCaller "step"` (a subject a root also reaches = a root path or L4's `support`, never `step`). Probes `coverage-step` (instance + class + `noCaller "step"` + `call`) + `coverage-step-binding` (driver + `embedded`): one plant per check, combined (a coverage run ≈ 5 GiB + the replay), each check named by its own expectation line; an `embedded` that does not decode leaves the module checks (call, classes) unrun ⇒ its plant shares no probe with them.
- Planted inputs = `tests/ledger/` (blind suite, tester-2): fixture modules `tool/FvdepLedgerFixtures/` (generated: `tests/ledger/generate.py` + `regenerate.sh` rebuild them byte-identically; layout = the generator's + lean-fmt's, outside `lean-style`'s line rules), cases `cases.tsv` + 8 seeded byte mutations of the doc; each breach → rc 1 naming its code, clean controls → rc 0, usage + load failures → rc 2. Its firing record = red on the accept-all stub checker (5fab964, branch `wt/tester-2`). A checker change reruns it; an expected value changes only on evidence that the case errs against the contract. Probes: `coverage` (one doc byte off → `ledger: root: doc:`), `ledger-suite` (a flipped expected rc → `FAIL T5`).
- Closed theorems count after an astra statement-faithfulness review (`.claude/rules/tiers.md`).
