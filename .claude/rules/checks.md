# Purpose-built checks + their probes

- An edit to a check (gate registry + aggregation + step ledger, `tree-clean`, `imports`, `preview`, `lean-style`, `fanout`, `vendor`, `vendor-upstream`, `deps`, `renovate`, `meta`, `spec`, `cli`, `coverage`, `ledger-suite`, `codec-suite`, `manifest-suite`, `library-suite`, `fuzz-replay`, `sys-suite`, `acceptance`, `python`, `secrets`, `vulns`, `workflows`, `tools/fetch-tools.sh`, `tools/ci-gate.sh` `ci_missing`, the compiler options + linters in either lakefile) reruns `tools/vflab-run bash tools/gate-probe.sh` (also the gate's `probes` stage): each check passes on a clean copy, fails on its planted input naming its cause, passes once restored. A new check lands with its probe.
- Probe copies share the gate tree's lean-fmt build through `FVDEP_LEAN_FMT` (a 339 MB package cache per copy otherwise); the gate's own `lean-style` builds + runs the pinned one.
- Stage `python` = pinned Ruff (correctness families E4, E9, E711–E722, F, B; `ruff.toml`) + Pyrefly (`pyrefly.toml`: preset `default` — without the file Pyrefly silently falls back to `basic`; unannotated bodies checked, warnings fail) over `tools/*.py` + `tests/**/*.py`; a suppression carries its reason on the line.
- Stages `codec-suite` (`tests/codec/run.sh`: tester-3's J, H, D + S5 cases), `manifest-suite` (`tests/manifest/run.sh`: tester-4's T6) + `library-suite` (`tests/library/run.sh`: tester-5's U4 A + B cases: the launch specs vs independent RFC 4648 + SemVer references, the protocol codec, `fvdep-dev oracle`; the A cases' credit = hand mutants of the specs, `tests/library/mutants.py`, which edits the tree in place ⇒ a vflab workspace alone) = blind suites over shipped code (`suite` in `tools/gate.sh`): the fast gate reuses a green verdict while the input closure stays byte-identical (the suite's files + the shipped code its driver builds + Lake configs + toolchain pins; jq's lock line for codec), the full gate always runs them; a run narrowed to one case (`FVDEP_CODEC_CASE`, `FVDEP_MANIFEST_CASE`, `FVDEP_LIBRARY_CASE`, `FVDEP_LEDGER_ONLY`) never writes the green mark. Expected values change only in their own unit, on evidence a case errs against the contract: codec's are pinned by `FROZEN-JH.tsv` + `FROZEN-JHD.tsv` (freeze guards inside `run.sh`; probes `codec-freeze-jh`, `codec-freeze-jhd`). jq = the pinned one, first on `PATH` for `codec-suite` alone (its output bytes are a printer oracle). Their Lean packages (`tests/codec`, `tests/manifest`, `tests/library`, `tests/sys`) take `lean-style`'s layout rules, not lean-fmt (it runs on `.` + `tool`, the root `.lean-fmt.toml` excluding `tests/**`: lean-fmt elaborates each file, and the packages build inside their own stages). A suite probe sets `with_suites=1` (copies the test packages' builds).
- Stage `fuzz-replay` (`tools/fuzz.sh replay`; contract U3 "Fuzz") = every committed corpus file (`tests/fuzz/<target>/`: seeds + every crash input, pinned) through each target's engine-free build: a Lean target (`tool/FvdepFuzz/*`: one `@[export]` round-trip property each, `panic!` on violation) = the IR C of its import closure (Lake's `.setup.json` `importArts`) + `tests/fuzz/lean.c` (sets `LEAN_ABORT_ON_PANIC=1`: a panic = the abort the engine counts) + `tests/fuzz/replay.c`; a C target under gcc ASan + UBSan; verdict reused like the suites' (`FVDEP_FUZZ_TARGET` narrows a run, which writes no mark); an abort names its input. Campaigns (campaign tier, never the gate) = `tools/fuzz.sh campaign TARGET SECONDS` + `cmin TARGET` over AFL++ built from `tools/afl.lock` (sha256-verified source tarball); scheduled CI = `.github/workflows/fuzz.yml` (weekly + dispatch, 1800 s per target; schedule + dispatch fire from `main` alone ⇒ a `ci/fuzz**` push proves a workflow change, 300 s per target; a crash or hang = red + its inputs as an artifact); a crash → its input pinned in the corpus + the fix in the same unit. `bash tools/fuzz.sh pin VERSION` prints the re-pinned lock line (a Renovate bump of the version column alone stays red on `renovate`).
- Stage `sys-suite` (`tests/sys/run.sh`: tester-4's F6; contract U3 F6) = the persistence shim + writer guard through the dev driver `fvdep-dev`: an `LD_PRELOAD` fault library scripting each syscall, crash cuts, lock contention between processes, the shim under gcc ASan + UBSan (`tests/sys/build.sh`); verdict reused like the suites' (`FVDEP_SYS_CASE` narrows a run, which writes no mark). Its case `F.filesystem.zfs` needs fvdep's ZFS dataset: a host with `/srv/data/fvdep` must hold `sys-test/` (`tools/vflab-provision.sh`; else exit 2); a host without it (CI runners) reports that case `SKIP` by name ⇒ it runs in the vflab full gate alone, and a green CI gate leaves it uncovered. Ruling on Engineering's skip clause (a skipped case earns a `.agent/deferred.md` row): this skip = a host condition, not a deferral — the case runs + must pass in every vflab full gate (the gate of record), so no row.
- Stage `acceptance` (shard `lean`, fast gate too) = `python3 -I tests/acceptance/run.py --merged` with `FVDEP_BIN` = the built `fvdep`: tester-1's blind cases whose `MANIFEST.tsv` status is `merged`; verdict reused like the suites' (input closure = the suite + the shipped code + Lake configs; `FVDEP_ACCEPTANCE_CASE` = a `-k` substring, a narrowed run writes no mark). Probe `acceptance`: a merged case's expectation flipped → `FAIL <id>:`. The scan fixtures' lockfiles are `fixture` lines in `tools/lockfiles.txt`; `deps` skips Lake manifests under `tests/`, `renovate` the ones listed as `fixture` (the scan fixture's `lake-manifest.json`).
- Stage `vulns`: `tools/lockfiles.txt` lists every lockfile of the tree (`fixture <path>` = a test input never installed: listed, not scanned); osv-scanner needs network (osv.dev); vendored C has no lockfile ⇒ each `vendor/*/lock.json` commit is queried at OSV by commit (a failed query = red, never clean).
- An edit to `tools/vflab-run` or `tools/vflab-reclaim.sh` reruns `bash tools/vflab-run-probe.sh` from the desktop.
- An edit to `tools/vflab-provision.sh` or `tools/vflab-agent-smoke.sh` reruns both from the desktop (a host change ⇒ announce it to the fvapi session first): smoke rc 0, or 3 while the token is absent.
- An edit to `renovate.json` records `tools/vflab-run bash -c 'npx --yes --package renovate@<release ≥ 7 days old> renovate-config-validator --strict renovate.json'` → rc 0 in the commit body.
- `tools/pin-tool.sh NAME VERSION` re-pins a tool (asset name = the current one with the version replaced; release tags tried: `v<v>`, `<v>`, `<name>-<v>`); a Renovate bump of the version column alone stays red on `renovate` + `tools` until re-pinned.
