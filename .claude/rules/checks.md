# Purpose-built checks + their probes

- An edit to a check (gate registry + aggregation + step ledger, `tree-clean`, `imports`, `preview`, `lean-style`, `fanout`, `vendor`, `vendor-upstream`, `deps`, `renovate`, `meta`, `spec`, `cli`, `coverage`, `ledger-suite`, `codec-suite`, `manifest-suite`, `library-suite`, `fuzz-replay`, `sys-suite`, `index-suite`, `sandbox-suite`, `isolation` (+ `tools/pidns-check.sh`), `oracle-suite`, `profile-suite`, `acceptance`, `index`, `python`, `secrets`, `vulns`, `workflows`, `tools/fetch-tools.sh`, `tools/ci-gate.sh` `ci_missing`, the compiler options + linters in either lakefile) reruns `tools/vflab-run bash tools/gate-probe.sh` (also the gate's `probes` stage): each check passes on a clean copy, fails on its planted input naming its cause, passes once restored. A new check lands with its probe; checks sharing a costly stage may share one copy — a combined plant whose expectation holds one line per check, every line named (`names_all`).
- Probe copies share the gate tree's lean-fmt build through `FVDEP_LEAN_FMT` (a 339 MB package cache per copy otherwise); the gate's own `lean-style` builds + runs the pinned one. A copy = the tree's file set committed with `git add -f` (a tracked file under an ignore pattern, e.g. a fixture below a `.lake/`, stays: every closure key in a copy = the tree's) + the pinned tools + the Lake build caches minus each `.lake/config` (Lake's elaborated lakefile bakes `__dir__`: a stale one links the tree's files; Lake re-elaborates it in the copy) — a probe whose check runs no Lean (builds nothing, runs no built binary) is declared `with_build=0` + skips the caches (a copy's bytes set its cost under concurrency; a misdeclared one fails its control or rebuilds from source) — + the keyed stages' green marks; a restore = its own files + git from a pristine copy, the tools + caches from the tree (no probe writes the tree's): `FVDEP_REUSE=1` throughout ⇒ a keyed stage's (`suite`) control + restored runs reuse the tree's verdict (closure = the tree's), the planted run alone executes; a plant outside the stage's key reuses a green there ⇒ the probe fails (each keyed probe proves its key covers the planted file; contract U1 P1 reuse). `probe` queues; `launch` starts `first` before the rest: the longest probes first (a long one started late sets the tail; each PROBE line ends with its wall-clock per phase), the index probes spread out (one lock: a planted index run builds the library).
- `lean-style` + `coverage` reuse a green verdict in the fast gate like the suites (`suite`; keys: every Lean source + the formatter's configs, pin + script; the tool package + library + `docs/verification.md` + `.agent/spec.md`); the full gate always runs them.
- Stage `python` = pinned Ruff (correctness families E4, E9, E711–E722, F, B; `ruff.toml`) + Pyrefly (`pyrefly.toml`: preset `default` — without the file Pyrefly silently falls back to `basic`; unannotated bodies checked, warnings fail) over `tools/*.py` + `tests/**/*.py`; a suppression carries its reason on the line.
- Stages `codec-suite` (`tests/codec/run.sh`: tester-3's J, H, D + S5 cases), `manifest-suite` (`tests/manifest/run.sh`: tester-4's T6) + `library-suite` (`tests/library/run.sh`: tester-5's U4 A + B cases: the launch specs vs independent RFC 4648 + SemVer references, the protocol codec, `fvdep-dev spec` (U4 B5's compiled-in launch specs); the A cases' credit = hand mutants of the specs, `tests/library/mutants.py`, which edits the tree in place ⇒ a vflab workspace alone; + the contract A8 conformance trial's build, `tests/library/conformance/`: a consumer package proving `@impl = @spec` + `@impl = Fvdep.Abi.V1_0_0.decoder @spec` from the spec modules alone, red on any axiom outside the standard three; probes `library-suite` (a reference-encoder plant) + `library-conformance` (an axiom in a trial proof → `encode_eq rests on`)) = blind suites over shipped code (`suite` in `tools/gate.sh`): the fast gate reuses a green verdict while the input closure stays byte-identical (the suite's files + the shipped code its driver builds + Lake configs + toolchain pins; jq's lock line for codec), the full gate always runs them; a run narrowed to one case (`FVDEP_CODEC_CASE`, `FVDEP_MANIFEST_CASE`, `FVDEP_LIBRARY_CASE`, `FVDEP_LEDGER_ONLY`) never writes the green mark. Their Lean packages (`tests/codec`, `tests/manifest`, `tests/library`, `tests/sys`) take `lean-style`'s layout rules, not lean-fmt (it runs on `.` + `tool`, the root `.lean-fmt.toml` excluding `tests/**`: lean-fmt elaborates each file, and the packages build inside their own stages). - Stage `fuzz-replay` (`tools/fuzz.sh replay`; contract U3 "Fuzz") = every committed corpus file (`tests/fuzz/<target>/`: seeds + every crash input, pinned) through each target's engine-free build: a Lean target (`tool/FvdepFuzz/*`: one `@[export]` round-trip property each, `panic!` on violation) = the IR C of its import closure (Lake's `.setup.json` `importArts`) + `tests/fuzz/lean.c` (sets `LEAN_ABORT_ON_PANIC=1`: a panic = the abort the engine counts) + `tests/fuzz/replay.c`; a C target under gcc ASan + UBSan; every replay under `RLIMIT_CORE` = 1 (+ ASan `disable_coredump=0`): a planted crash dumps no core + never reaches vflab's `core_pattern` pipe (apport, as root; the kernel skips a pipe at that limit alone); verdict reused like the suites' (`FVDEP_FUZZ_TARGET` narrows a run, which writes no mark); an abort names its input. Campaigns (campaign tier, never the gate) = `tools/fuzz.sh campaign TARGET SECONDS` + `cmin TARGET` over AFL++ built from `tools/afl.lock` (sha256-verified source tarball); scheduled CI = `.github/workflows/fuzz.yml` (weekly + dispatch, 1800 s per target; schedule + dispatch fire from `main` alone ⇒ a `ci/fuzz**` push proves a workflow change, 300 s per target; a crash or hang = red + its inputs as an artifact); a crash → its input pinned in the corpus + the fix in the same unit. `bash tools/fuzz.sh pin VERSION` prints the re-pinned lock line (a Renovate bump of the version column alone stays red on `renovate`).

- An edit to `tools/vflab-run` or `tools/vflab-reclaim.sh` reruns `bash tools/vflab-run-probe.sh` from the desktop.
- An edit to `tools/vflab-provision.sh` or `tools/vflab-agent-smoke.sh` reruns both from the desktop (a host change ⇒ announce it to the fvapi session first): smoke rc 0, or 3 while the token is absent.
