# U2 Pure core + coverage ledger — contract (agent-read)

Sources: `.agent/spec.md` Decisions (Self-verification + its scope, Conformance method, Verification profile, Proof policy, Public interface, Data formats, Lifecycle, Domains), `docs/interface.md` §2–§6, `docs/library.md` Naming, `.claude/rules/tiers.md` + `tests.md`. U2 = the pure decision core later units call + the gate that binds every claim about fvdep's own code to a checked theorem about the executed function on its shipped call path. Commands using the core land in U8; persistence primitives (durable replace, fsync FFI, fault injection), codecs + key digests in U3; observation producers (sandbox, phases, kernels) in U5–U7.

Tiers: **kernel** = every predicate below. I/E/P/X = proof targets: each a closed theorem about the shipped function, its own property test (`.claude/rules/tests.md`); every definition + theorem → one statement-faithfulness review (astra) before credit. L = gate predicates: a blind `tester` fixture suite (L9) + MAIN's probes. **residue (tested)** = the interpreter's effect → primitive mapping (X6): the U1 K2 smoke cases.

Lean layout: `tool/FvdepCore/{Ids,Evidence,Status,Plan}.lean` (+ `Cli.lean`), `tool/FvdepIO/Run.lean` (interpreter), `tool/FvdepLedger/*.lean` + exe `fvdep-ledger` (gate tool, never shipped, imports `Lean`), lean_lib `FvdepLedgerFixtures` + `tests/ledger/` (L9).

## Ledger (gate stage `coverage`, shard `lean`)

- L1 Data = one `FvdepLedger.Ledger` value (literal terms; the checker decodes them from the elaborated definitions): root (`main`, `interpreter`, `plan`), `libs` (shipped lean_lib roots), rows, residue. Row = component (module), contract (reference text), claim (text), claims (list of (statement, theorem): statement = a `Prop` definition in the ledger modules = the claim's exact proposition; theorem = the shipped theorem proving it), subject (the executed function), path, `noCaller` (unit id or empty), residue ids (assumptions), unproven ids (parts without a theorem). Residue entry = id, what, reason, ruling (a text that must occur verbatim in `.agent/spec.md` Decisions), boundary (declarations allowed to be opaque/extern/implemented-by there).
- L2 Coverage: every owned definition reachable from `main` (closure over definition values; owned = defined in `Main` or a module under a root starting with `Fvdep`, by module metadata) lies in the closure of some row's subject; every owned module defining such a definition, and every module under a `libs` root that defines one, is some row's component; each subject is defined in its row's component. Red names the definition or module.
- L3 Claims: each theorem exists as a theorem; its type is alpha-equivalent to its statement's value (same universe parameters); its axioms ⊆ {propext, Classical.choice, Quot.sound}; some statement of the row mentions the subject; a row without claims has nonempty `unproven`; every residue + unproven id names a residue entry; every entry's `ruling` occurs inside the `## Decisions` section of `.agent/spec.md` (the review checks it rules that residue). Red names row + cause.
- L4 Root + paths: `main`'s value = `fun a => interpreter (plan a)` exactly. A nonempty path starts at `main`, ends at the subject; edge `main → x` needs `x ∈ {interpreter, plan}`; edge `a → b` (a ≠ `main`) needs `b` in a's closure and a statement of the row mentioning both: a bridge proposition stating a's result (or trace) in terms of b's. Mentioning both is the mechanical floor; the faithfulness review rejects a statement that leaves a's result unconstrained by b's (e.g. `(a x = a x) ∧ (b x = b x)`). A subject reachable from `main` needs a valid nonempty path (a stale `noCaller` is red) unless `noCaller` = `support`: a supporting component (shared helpers such as the plan monad, literal data) whose subject lies in the closure of a row with a valid nonempty path = the mechanical condition (whether its claims serve those rows = the faithfulness review's judgment; L3 alone governs a support row's claims, none + nonempty `unproven` included); any other empty path needs `noCaller` = a unit whose Tasks row in `.agent/spec.md` is open (`- [ ] <unit> `). Rows never take the root `main` as subject (code `subject`); `main` itself is exempt from L2 (L4's shape covers it).
- L5 Compiled = checked: in the closure of each claim-bearing row's subject + its path elements (but `main` + `interpreter`), every owned constant's compiled code is its kernel definition — none carries `@[implemented_by]` or `@[extern]`, none is `partial`, `unsafe` or `opaque` — unless it is a boundary declaration of a residue entry the row cites. Red names constant + attribute.
- L6 Replay: toolchain `leanchecker` with every owned module of the loaded environment as an explicit target (replay covers only the targets' own constants, so each owned import is a target; a fixture run loads its fixture module alone); nonzero → red with its first error line.
- L7 Doc `docs/verification.md` = the rendering: root; per row: component, contract, claim, each statement pretty-printed (width 100, notation on, `pp.deepTerms` on: never truncated) + its theorem + the statement's `Expr.hash` (hex). The exact record = the statement's committed definition, held to the theorem's type by L3's term equality; the rendering + hash = presentation + drift detection, subject, path, uninterpreted owned constants in the closure (residue boundary declarations), residue + unproven (with reasons); then the residue. `--write` regenerates; `--check` compares bytes, red names the first differing line.
- L8 Interface: `fvdep-ledger (--check|--write) <doc> [--module <M>] [--ledger <decl>] [--spec <file>]` (defaults `FvdepLedger.Rows`, `FvdepLedger.Rows.ledger`, `../.agent/spec.md`; run in `tool/` via `lake exe`). rc 0 = every check held (+ doc equal, or written); 1 = findings, one stderr line each `ledger: <component|root>: <code>: <detail>`, nothing written; 2 = usage, module or ledger missing or not literal. Codes: `uncovered` (L2 definition), `module` (L2 module without row), `subject` (subject missing or outside its component), `theorem` (missing or not a theorem), `statement` (type ≠ statement, or statement not a `Prop` definition), `axiom`, `about` (no statement mentions the subject), `waiver` (no claims + empty unproven), `residue` (unknown id), `ruling` (ruling text absent), `root` (L4 shape), `path` (endpoints or `main` edge), `edge`, `nocaller`, `compiled` (L5), `replay` (L6), `doc` (L7).
- L9 Fixture suite (tester-2, blind, from this contract): fixture ledgers in `FvdepLedgerFixtures` with their own roots — one per breach: bypassed subject, retained-but-unused subject reference with a weakened theorem, theorem type ≠ statement, `sorry`, axiom outside the set, forged theorem in an owned import (std axioms alone), uncovered reachable definition inside a covered module, waiver without residue, residue without ruling, stale + closed-unit `noCaller`, `implemented_by` / `extern` / `partial` / `unsafe` / `opaque` inside a proved closure (directly + transitively), broken root shape, doc drift → rc 1 naming the cause; clean fixtures → rc 0; usage + load failures → rc 2. The gate runs the suite in stage `coverage`; its probes reuse it (one build).

## Ids (`FvdepCore.Ids`; `docs/library.md` Naming)

- I1 `ModuleId` = dep `[a-z][a-z0-9]*` + op = `_`-joined segments `[a-z][a-z0-9]*` (each segment starts with a letter: sharpens Naming so I3 is injective; recorded in `docs/library.md` + Decisions); text `<dep>.<op>`; theorems: `parse (toString m) = some m`; `parse s = some m → toString m = s`.
- I2 `EntryVersion` = (major, minor, patch : Nat), text `x.y.z` (decimal, no leading zero, nothing else); round trip both ways; order = numeric by field in that order (the library-entry order; package SemVer comparison = U4's `semver.compare`); theorems: total, antisymmetric, transitive, `compare` consistent.
- I3 Lean module of (id, version) = `Fvdep.<C dep>.<C op>.V<x>_<y>_<z>` (C = each segment's first letter upper-cased, segments joined); theorem: injective in (id, version).
- I4 `ModuleRef` = `<id>` | `<id>@<x.y.z>`; round trip both ways.
- I5 Reserved consumer module names: first component `Init`, `Std`, `Lean` or `Lake`, or starting with `Fvdep` (every fvdep library + the tool's: `FvdepCore`, `FvdepIO`, …); recorded in `docs/library.md` (replaces its `FvdepTool` list entry). Theorems cover the whole `Lean.Name` domain: a one-component string name by its spelling; a string or numeric component after the first never decides; the empty name + a numeric first component are never reserved.
- I6 `Commit` = 40 lowercase hex; round trip both ways.

## Evidence → result (`FvdepCore.Evidence`)

- E1 Keys: `RequestKey` = id, version, shape (fn | abi), evidence kind, implementation + proof constant names, adapter argv (differential entries; U3 D3: the receipt names what ran), digests of the requested source closures (spec closure; implementation + proof sources | adapter). `Profile` = qualified verification profile: id, required kernels (by type: Lean, con-leche, NanoDa — never empty), axiom allowlist. `ChallengeKey` = request key + library commit + the qualified profile itself (id + allowlist: a result judges by the challenge's profile, by construction) + statement digest.
- E2 Observations carry their challenge key + the phase outputs they judge: implementation profile accepted | refused (code ∈ `profile_construct`, `import_not_allowed`, `reserved_module`; file, line, detail); phase 1 built (export e1) | failed; phase 2 built (solution export e2, on e1) | failed; statement matched | mismatch (e1, e2); graph matched | mismatch (e1, e2); axioms (names; e2); kernel k accept | reject | crash | timeout (s) | decline (detail) (e2); infrastructure (code ∈ `sandbox_setup`, `tool_missing`, `adapter`, `fetch_failed`, `io`; detail); differential comparison (op, input, supported matched | mismatch (got, want) | unsupported; adapter digest).
- E3 Attribution: an observation counts iff its challenge key = the request's + its export bindings = the attributed phase outputs (phase 1's single successful export; phase 2's single successful export on it). After a failed phase 1 or 2 no later observation is attributable (no export to bind to), so a later-phase protocol violation arises after phases 0, 3, 4, 5 alone. Identical duplicates count once; two different responses for one phase or kernel, or an attributed observation of a phase after the first failed one = protocol violation (infra `internal`). Theorems: `result c (attributed c os) = result c os`; an observation under another key never changes the result; appending an identical duplicate never changes it.
- E4 `Result` = `infra cause negatives` | `verdict v reasons` (v ∈ proven, not_proven, matched, mismatch; reasons nonempty ↔ v ∈ {not_proven, mismatch}). Theorem: a verdict names reasons ⇔ it is NOT PROVEN or MISMATCH.
- E5 Proof rule, in order: (1) an attributed infrastructure observation or protocol violation → infra (negative reasons seen so far kept); (2) phases implementation profile → phase 1 → phase 2 → statement → graph → axioms → kernels: the first failed phase → not_proven with its reasons (axioms: each outside the allowlist named; kernels: every non-accepting required kernel listed, `kernel_decline` never reported as `kernel_reject`); a phase missing with no earlier failure → infra `missing <phase>`; (3) else proven. As phase facts (`Spec`, membership premises only): in phase order, each phase's attributed responses = two different ones → protocol; none → missing; one failing response → its reasons (a later-phase observation present → protocol, reasons kept); once all pass, the kernel step (`KernelSpec`, apart from the executed `kernelWalk`) over each required kernel's attributed answers: a kernel with two different answers → protocol; else a silent kernel → missing `kernel`; else all accept → passed, any other answer → failed; every outcome lists each kernel that answered once without accepting (its E5a code + the kernel), in kernel order Lean, con-leche, NanoDa (theorem `kernelWalk_spec`); the result = the first attributed infrastructure observation's code beside the walk's negatives, else the walk's outcome (protocol + missing → `internal`, negatives kept). Theorem: `result_spec`.
- E5a Public codes (interface §6 vocabulary): implementation profile refusals keep their codes; phase 1/2 failure → `build_failed`; statement → `statement_mismatch`; graph → `graph_mismatch`; axioms → `axiom`; kernels → `kernel_reject` | `kernel_crash` | `kernel_timeout` | `kernel_decline`; infrastructure keeps its code; protocol violation + missing phase → `internal` (new interface code: fvdep's own evidence pipeline broke its protocol; exit 2); differential mismatch → `mismatch`; zero supported comparisons → `adapter`.
- E6 Theorems: PROVEN ⇔ a proof request whose observations under its key hold every observation of a passing proof on some exports (axioms ⊆ allowlist) + nothing else but identical duplicates, observations bound to other exports + comparisons (`proven_iff`: soundness + completeness over every serialization); infra never carries a verdict; isolation (E3).
- E7 Differential rule: attributed comparisons + adapter infrastructure alone; matched ↔ ≥ 1 supported comparison ∧ all supported match ∧ no infra; mismatch ↔ a supported mismatch ∧ no infra; zero supported → infra `adapter`; never proven; a proof request never reads comparisons. Identical comparisons count once; an infrastructure observation → infra with its code, the mismatches seen kept.

## Status (`FvdepCore.Status`)

- P1 `meets : Policy → Result → Option Retraction → Bool`: infra → false; `required` ↔ proven ∧ not retracted; `development` ↔ proven ∨ matched (retracted allowed); theorems both directions.
- P2 `moduleExit` = infra → 2, meets → 0, else 1; `commandExit` = maximum (2 > 1 > 0; empty = 0); theorems: = 0 ↔ all 0; = 2 ↔ some 2. Exit codes 0/1/2; `moduleExit` = 2 ⇔ infra, = 0 ⇔ meets; `checkExit` = 0 ⇔ every fresh result meets the policy, = 2 ⇔ some fresh result is infra.
- P3 `Receipt` = common fields (request key, library commit, verification profile id, policy, checked time) + evidence: proof (all proof digests incl. e1 + e2) | differential (spec + adapter digests); `receiptOf` = some only for a well-shaped request (proof: shape, implementation + proof constants, both source digests, no adapter argv or digest; differential: the adapter argv + its digest alone) whose kind matches the result (proof request PROVEN with its exports → proof receipt; differential request MATCHED → differential receipt); the verdict is derived from the constructor (schema 1 has no verdict field); theorems both ways.
- P4 `Inputs` = manifest request + current input digests + library commit + profile id; `changes : Receipt → Inputs → List Change` (fixed field order; checked time + exports never compared). `changes` = exactly the differing input fields, in report order (`inputFields`).
- P5 `agreement : Manifest → Lock → List Disagreement` (module sets, per-module requests, the shared library commit); any disagreement → no module delivered; `status` + `check` report it; `check`'s exit unchanged. Theorem: exactly the disagreements, each with its cause (library pins differ; a manifest module without a lock entry, with several, or with one for another declaration; a lock entry for an unlisted module).
- P6 `delivered` = agreement empty ∧ proof receipt ∧ no changes ∧ not retracted in the status snapshot (≠ the source pin); `statusReason` = the first of: disagreement, `no lock entry`, `the proof was checked under an older verification profile`, `lock entry is stale (<what changed>)`, `test evidence only`, `retracted (<reason>); replacement <ver>|no replacement`; theorem: `statusReason = none ↔ delivered`. Public codes: disagreement, no lock entry, test evidence only → `not_delivered`; older profile + stale inputs → `stale_receipt`; retracted → `retracted`. Theorem: the reason = the first that applies, with its payload.
- P7 `statusExit`: `required` → 0 ↔ agreement empty ∧ every module delivered; `development` → 0 ↔ agreement empty ∧ every module's receipt current (proof, retracted proof or differential); else 1 (2 = U8 setup failures). A disagreement fails `status` under either policy, also with no manifest module (Decisions `Core rulings`).
- P8 `retraction` = the first notice naming (id, version) in the snapshot's list; appending notices never removes one (monotone); a listed (id, version) is never delivered. Theorems: the retraction = the first matching notice's reason + replacement; none ⇔ no notice names (id, version).
- P9 `lockDecision` = commit ↔ every module meets the policy, else refuse with `commandExit`; a refusal's exit = `checkExit`; `lockState` (no_entry | current | out_of_date changes) for `check`: changes = exactly the differing fields in report order, P4's inputs then the policy + the exports (`lockFields`), so an out-of-date entry always names one; `checkExit` takes the fresh results alone.

## Effect plan (`FvdepCore.Plan`, interpreter `FvdepIO.Run`)

- X1 `Plan α` = free monad over `Eff`: `out s`, `err s` (no failure branch: a failed output write interrupts the run, interface §2), `read f : Except String (Option Bytes)`, `replace f bytes : Except String Unit` (ordinary failure = an `Except` the continuation handles); `File` = lock | manifest. Trace semantics: events = (effect, response); a run ends `some a` (completed) or `none` (interrupted after any prefix).
- X2 `WriteSet` = lock : Option Bytes, manifest : Option Bytes; `commit ws` replaces lock, then manifest (those present) and stops at the first error, returning (file, reason).
- X3 `authorize policy results ws` = `lockDecision` first; refuse → its exit, no replace event in any run; commit → `commit ws`, a failure → exit 2 + `Could not finish writing <file>: <reason>. Run "fvdep status" to see the state.` on stderr; theorems: a replace event ⇒ the decision was commit; replace events follow the canonical order + stop after the first failed one. A complete run after a commit decision = every replace succeeded + exit 0 (the write set's files in canonical order), or the first failed replace, its diagnostic + exit 2; every replace succeeding ⇒ that run exists.
- X4 Atomic-replace relation (success → new; error or interruption → old or new: a rename can land before a failed directory fsync; U3 implements + fault-injects the primitive) ⇒ after any run, each file holds its old or its new bytes.
- X5 `Cli.plan args` = `out` of `(Cli.run args).stdout`, `err` of its stderr (each when nonempty), result its exit; theorem: a completed run's events = those outputs; never `read`/`replace`.
- X6 Interpreter (residue): `out`/`err` → putStr + flush, failure → exit 2 + `Could not write the output: <reason>.` (broken pipe quiet); `read`/`replace` → U3 (until then `.error`, no write; no U2 command emits them).
