## T Toolchain, recipes, limits

- T1 Preflight (residue): the sysroot of I1 (`lean --print-prefix` run in a fresh run directory whose `lean-toolchain` names fvdep's own release, elan resolving it) holds `bin/lean` + `bin/leanexport`; `bwrap` = the first on `PATH` (the environment = trusted input: a wrapper earlier on `PATH` is a supported test seam), `bwrap --version` ≥ 0.8.0 (`--disable-userns`; `--size` since 0.7.0); a missing or older tool → `Obs.infra toolMissing` naming it, exit 2. - T2 Recipe (versioned, pure data, in every K1 key + P record): id; the toolchain release + fingerprint (T1); argv template; `LEAN_PATH` order (`/fvdep/lib:/fvdep/prior`: the library view, then the check's consumer modules built so far in one directory — Lean resolves a module's root component to the first entry holding that directory, so a namespace split across two entries loses its later modules, measured: phase 2's `SandboxTrial.Proof` beside phase 1's `SandboxTrial.Impl` in another entry = "does not exist"); environment; options (`-D`); thread count (fixed: Lean's default reads the core count). `consumer/1` = Lean's default options for consumer modules (U6 governs their syntax), `library/1` = fvdep's qualified elaboration options (`FvdepIO.Index.lakefile`'s: `autoImplicit=false`, `relaxedAutoImplicit=false`, `warningAsError=true`, the `linter.extra.*` + `linter.redundantVisibility` set) for library modules; both `--json` (diagnostics as JSON lines, B1) + `-j 4`; `-M` + `-T` stay unset (Lean reports their exhaustion as an ordinary error, exit 1, which P5 would read as a refusal of the input; the deadline + a host OOM kill are P5's resource cases instead). - T3 Limits (typed; U5 fixes defaults, U7 qualifies the production values under stated load): `phaseDeadline` (absolute, monotonic, from the phase's first compile through its export), `fillBudget` (a cache fill, own deadline), `lockWait`, `workBytes` + `tmpBytes` (tmpfs sizes), `diagnosticBytes` (per stream, R3), `frameBytes` (R8), `exportBytes`, `sourceBytes` (`SourceLimits`: 1 MiB per file, 16 MiB per snapshot, both inclusive: supported checking inputs, not the spec's domain; no outside setter in U5), `fileBytes` (every step process's `RLIMIT_FSIZE`, R8; default `workBytes / 8`). ## P Phases + exports (`FvdepCore.Phase` pure; `FvdepIO.Phase` residue)

- P0 Lifetimes: a step's staging (its tmpfs + the run directory's per-step inputs) dies with the step; the command's frozen records (`phase1/`, `phase2/`, `exports/`, each artifact's digest) live in the run directory from their step to the command's end, through U7's judge, then go with it (R7); nothing is retained across commands but K's cache + B's bundles — U9 reconstructs phase 1 (P7), never relies on a retained record.
- P1 Step plan (pure `steps`): one sandbox per module compile (a compile sees earlier modules through their frozen artifacts alone), in K2's order, then the consumer roots check, then the export step; the phase deadline is absolute across them (the window opens at its first step; a step it leaves no time = `timedOut`, never spawned). Phase 1's library roots check runs before the window under its own bound (`fillBudget`): it imports library modules alone, so no consumer code reaches its exit (an absent library root = exit 2 whatever the consumer's code).
