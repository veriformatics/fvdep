## L Library snapshots (`FvdepCore.Library` pure; `FvdepIO.Library` residue `git`, `library-store`)

- L1 Source = `FVDEP_LIBRARY_URL` (unset or empty → `https://github.com/veriformatics/fvdep`; any git remote or local repository path; trusted input). A URL = git's rule (`url_is_local_not_ssh`, Linux: a `:` before any `/` — `scheme://…`, the scp-like `host:path`), anything else a local path. Its key = full SHA-256 hex over the anchored source's UTF-8 bytes (two unequal spellings = two unequal inputs ⇒ a shared key = a SHA-256 collision: separation rests on SHA-256's collision resistance): a local path made absolute against the working directory at invocation (before any directory change; the key separates one relative spelling in two directories without contacting either), a URL as written. Credentials inside a URL never reach a stored record or a diagnostic (`<url>` printed with its userinfo replaced by `***`).
- L2 Store `FVDEP_CACHE/library/v1/<source key>/`: `trees/<commit>/` (a published snapshot: complete, immutable, published by one rename, its `.complete` marker written last), `head.json` (L5), `lock` (flock: fetch + read + publish + `head.json` per source; acquired within T `lockSeconds`, default 60, else `infra io: the library store of <source> stayed locked`; a pin whose tree is published is served without it: a complete tree is never removed), `tmp/` (an attempt's private bare repository `<pid>.<n>.git`, its requests file `<pid>.<n>.requests` + the tree under construction `<commit>.<pid>.<n>`, removed after the attempt whatever its result; every entry removed once the lock is held: a holder's temps are its own, so any found = a dead attempt's). A `trees/<commit>/` without its marker = incomplete: removed + rebuilt under the lock, never read.
- L3 Fetch (residue `git`): a fresh private bare repository `tmp/<pid>.<n>.git` per attempt (`git init --bare -q --template=`), removed after the attempt whatever its result (a failed `fsck` leaves objects behind); `git fetch --depth=1 --atomic --no-tags --no-prune --no-recurse-submodules --no-auto-maintenance --no-write-commit-graph --no-write-fetch-head --refmap= -- <source> <refspec>`, refspec `+refs/heads/main:refs/fvdep/head` (head) | `+<pin>:refs/fvdep/pin` (pin; servers that refuse an unadvertised commit = a fetch failure, researcher-14 G1). `--depth=1` also refuses git's dumb-HTTP walker (it skips `fsck`). Config (`-c`): `fetch.fsckObjects=true` + `fetch.fsck.{badFilemode,gitattributesSymlink,gitignoreSymlink,gitmodulesParse}=error`, `core.hooksPath=/dev/null`, `core.fsmonitor=false`, `credential.helper=` + `credential.interactive=false`, `core.sshCommand=ssh -o BatchMode=yes`, `http.followRedirects=false`, `transfer.bundleURI=false`, `promisor.acceptFromServer=none`, `gc.auto=0`. After the fetch: the fixed ref's direct target is a commit (`git cat-file -t refs/fvdep/<ref>` = `commit`; a tag is refused), a pin's equals the pin. git = `git` through the caller's `PATH` (`posix_spawnp`; the `PATH` passed is the one searched), its own process group, exactly that environment, stdin from a file (`cat-file`'s requests) or `/dev/null`, every descriptor ≥ 3 closed. Each git process (init, fetch, the ref check, each listing, the batch) runs under T `fetchSeconds` (default 300) from its start: past it (or past its stdout cap, L4) the process group is killed — before the reap: an unreaped leader keeps its group id from reuse — then reaped; a fetch past its deadline = `git fetch passed its deadline of <n> seconds` (the no-fallback class, L6). Diagnostics: both streams captured concurrently (≤ T `gitBytes`, default 64 KiB each: diagnostics alone); a failed command's reason = the first nonblank stderr line within its kept bytes, trailing CR + blanks dropped, the source's spelling replaced by its redacted form + each other copy of its userinfo by `***` (git prints the URL it was given), then §1's line rule; no such line → its exit.

## E Entry resolution (`FvdepCore.Oracle.resolve` pure; two U5 export steps over one view)

- E1 Order (each stage before the next; a refusal ends the run, stdin unread): grammar (`<id>@<ver>`: library.md Naming) → P → L → L7 → `index.json` (≤ 1 MiB) decoded by U4's `decodeIndex` → the target's row among `operations` (a `removed` record is not active; a notice does not erase an operation: a retracted, still-listed operation is served, no delivery claim) → absent → `unknown target <target>`, exit 2; listed → E2.
- E2 Coherence (pure over K's discovery: the header graph + the source bytes K read for the build): the entry module `Fvdep.Registry.<Dep>.<Op>.V<x>_<y>_<z>` present; the index's toolchain = the tree's; the row's digest = U4 C4's `entryFrame` digest recomputed over the entry module's own import closure (library modules reached from it alone, by the header graph: the view's extra Version root never enters it) + their raw source bytes at their `A/B.lean` paths (measured at U5b-A on vflab: `FvdepIO.Cache.discover` from the entry module + `FvdepCore.Hash.frame "fvdep/entry/1"` + SHA-256 reproduce `index.json`'s digests of `base64.decode` (6 files), `base64.encode_url` (5), `semver.compare` (4)); a listed target failing any of these → `the library snapshot <commit> is inconsistent: <reason>`, exit 2 (never `unknown target`).
- E3 Export 1 (imports = [entry module], roots = [`<module>.entry`]) → X → `<module>.entry` must be a `def` with a value → U4 C2's `decode` with `moduleForm` + empty read-through facts → `entryOf (.entry module payload)` → `id` + `version` = the target's (else E2's inconsistency); `spec` = `S.<fn>` with `S` = the spec module (library.md Naming: `Fvdep.<Dep>.<Op>.V<x>_<y>_<z>`), its components plain (U3 T3, the form P4 passes on argv + W writes into Lean source).
- E4 Export 2 (imports = [S], roots = [spec]) → `spec` must be a `def` → its type → `sigOf` (U4 B: every B1 shape — bytes as `List UInt8` or `ByteArray`, text, utf16, nat, int, ordering, version; plain or `Option` results; any positive arity) → `Sig` (op = `fn`); a type `sigOf` refuses → `the spec of <target> has a type the adapter protocol cannot carry`, exit 2.
- E5 Supervisor work bound: before C2's decoder runs, the entry value's zeta-expanded size (memoized over the export's DAG) ≤ T `decodeNodes` (default 10^6), else `infra io: the registry entry of <target> exceeds <n> nodes` (C2's decoder revisits shared + `let` values: `.agent/review.md` U4 rows); measured on the six launch entries before the default is fixed.
- E6 Claim (`OracleClaims.resolveExact`): `resolve` returns (spec, sig) exactly when the target is an active listed operation, the coherence checks hold, the entry value's expanded size is within E5's budget, the entry decodes as a `def` with the target's id + version + a plain `S.<fn>` spec, + `sigOf` accepts the spec `def`'s type; a refusal = the first failing stage in E1–E5's order.

## W Internal wire codec (`FvdepCore.Oracle.Wire` pure; the same source runs inside the step)

- W0 Modules: the protocol's types (`Ty`, `RTy`, `Val`, `Reply`) move from `FvdepCore/Protocol.lean` into `FvdepCore/Protocol/Types.lean` — same namespace + names, imports `Fvdep.Semver.Version.V1_0_0` alone (`Val.version`'s type) — so every credited U4 B statement keeps its term (`tools/ledger-doc.sh`: those rows' hashes unchanged); `FvdepCore/Oracle/Wire.lean` imports Types alone. Inside the step `Driver.lean` = `import <entry module>` + `import Fvdep.Semver.Version.V1_0_0` + the two modules' text after their `import` lines, verbatim (embedded in fvdep at build time) + the generated `main`; Q4's check: the embedded texts = those files' bytes at build time (a stale embedding fails).

- W1 One request = one line: its arguments in order, space-separated, each `<tag>:<payload>`: `b:<hex>` bytes (both representations), `t:<hex of UTF-8>` text, `u:<hex of UTF-16 code units, 4 digits each>` utf16, `n:<decimal>` nat, `i:<decimal, - prefix when negative, no -0>` int, `o:lt|eq|gt` ordering, `v:<major>.<minor>.<patch>/<pre>/<build>` version (`pre` = `.`-joined `n<decimal>` | `a<hex of UTF-8>`, `build` = `.`-joined `x<hex of UTF-8>`; an empty list = empty, an empty identifier keeps its tag); every payload over `[0-9a-z.:/-]` ⇒ delimiter-safe, canonical (lowercase hex, decimals without leading zero).
- W2 One result = one line: `ok <tag>:<payload>` (the result's value) | `err` (an `Option` result's `none`; `err` for no other type).
- W3 Functions (pure, in fvdep + shipped as source into the step): `encodeArgs : List Val → String`, `decodeArgs : List Ty → String → Option (List Val)`, `printResult : Val → String` + `printNone`, `parseResult : RTy → String → Option Reply`; the native bridge = W's own class `Native α` (`toVal : α → Val`, `ofVal : Val → Option α`) with instances for every served representation — `List UInt8`, `ByteArray`, `List Char`, `List UInt16`, `Nat`, `Int`, `Ordering`, `Fvdep.Semver.Version.V1_0_0.Version`, + `Option α` for results.
- W4 Claims (`WireClaims`; spec = W1–W2's grammar written apart): `argsExact` (`decodeArgs ts s = some xs ↔ xs.map ty = ts ∧ s = argsLayout xs`), `resultExact` (`parseResult t s = some r ↔ Typed t r ∧ s = resultLayout r`), + `printResult`/`encodeArgs` = the layouts; `nativeExact` (per instance: `ofVal v = some x ↔ v = toVal x`, + `toVal x` has the instance's `Ty`). Order, every Version value (atypical identifiers included) + every representation inside the domain.
- W5 The driver's conversions = W3's functions + W's `Native` instances, the generated `Driver.lean` holding W's source verbatim (fvdep embeds its own `FvdepCore/Oracle/Wire.lean` text at build time) + the typed application: W's `serve` applies the spec constant (`@S.fn`, explicit application whatever its binder annotations) to the decoded arguments recursively through `Native.ofVal`, one per signature argument in order (no arity table), its result through `Native.toVal` + `printResult`. ## V Evaluation (`FvdepCore.Oracle` pure merge; one U5 step)

- V1 Input: stdin read in bounded chunks to its end (> T `requestBytes`, default 64 MiB → `infra io: oracle, input: the batch exceeds <n> bytes`, exit 2, before any line is materialized); lines split by byte offsets (an empty input = zero requests, empty stdout, exit 0; a blank line = one request, refused by `decodeRequest`).
- V2 Each line → `decodeRequest sig` → `invalid <reason>` (supervisor-made: its encoded reply charged to T `batchBytes` at once, before the next line is read) | typed arguments → W's `encodeArgs` into `requests.txt` (staged bytes ≤ T `stagingBytes`, default 256 MiB, else `infra io: oracle, input: …`); retained per line: an invalid reply's index + reason, or a valid request's rank — never a batch-wide decoded value list.
- V3 No valid request → no step. Else one step over the view (`consumer/1`'s environment + `LEAN_PATH`, cwd `/fvdep/src` holding `Driver.lean` + `requests.txt`, both read-only): `lean --run Driver.lean` writes `out/replies.txt` alone; deadline T `oracleSeconds` (default 300), U5's limits; `pass` + exactly one framed file `replies.txt` required, the step's stdout never read as a result. A step not `pass` → `infra io: oracle, evaluate: <U5's typed cause>` (a signal by name; `SIGXFSZ` with the per-file cap: `signal 25 (per-file limit <n> bytes)`), exit 2. The frame ≤ `min(fileCap, frameBytes − 130)` bytes of replies on that success path (H2: tag, count, two framed paths, the canonical code-0 status).
- V4 Merge (pure `merge sig decoded replyBytes`): the step's lines (one per valid request, LF-terminated, each `parseResult (sig's result)`) + the invalid replies at their request indices → `List Reply`; a missing, extra, malformed or mistyped line → `infra io: oracle, evaluate: the driver's reply <k> is malformed`, exit 2. Encoded batch (every `encodeReply` byte) ≤ T `batchBytes` (default 128 MiB, counted incrementally while encoding: a blank-line batch alone could reach 30 bytes per input byte) → else `infra io: oracle, output: the encoded batch exceeds <n> bytes`, exit 2 — all before the first stdout write (I5).
- V5 Claim (`OracleClaims.trace`): over every input + every step answer — `merge` returns replies exactly when the step's lines parse one per valid request; then reply k = `invalid r` when request k's `decodeRequest` refused with r, else the parsed result of the step's line at request k's rank among the valid ones; the reply count = the request count. Conditional link (`OracleClaims.wireLink`): for typed arguments `xs` W's `encodeArgs` writes, the driver's `decodeArgs` returns `xs` in order; a result line it prints for `r` parses back to `r`.
- V6 Measured (vflab spike, a D2 step over a K-built view; single-sample feasibility, not a limit): the base64 `decode` entry's closure cold = 25.3 s; 300 requests (one carrying a 65,536-byte input as 87,384 characters, beyond the public string bound: driver stress only) evaluated in one step = 9.8 s (`replies.txt` 983,596 bytes); export 1 = 0.8 s, 10,951 lines (a separate `leanexport` run outside the step parsed by J: every line accepted). Re-measured on the product at U5b-O.
