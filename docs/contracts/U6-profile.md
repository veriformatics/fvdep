# U6 — implementation profile v1 (contract; agent-read)

Requirement: Decisions "Conformance method" (2) — before any build, a trusted parse checks every implementation module against a positive allowlist over the whole tree (commands, terms, tactics, attributes, options); imports ⊆ Init, Std, the fvdep library + the manifest's implementation modules; reserved module prefixes refused; an unlisted kind ⇒ NOT PROVEN naming file:line + kind. Library admission (U7) runs the library's phase-1 modules (spec, model, registry) through the same profile. v1 freezes once the qualification corpus (Q) passes; each extension = a new version + requalification + regressions. Review: consultant-12 rounds 1–2 (round 1: 1 accept, 8 amend, 1 reject; round 2: 3 closed, 5 open, 1 new gap — fixed after the bound by MAIN), folded in; U6-A2 = the test seam (D), the typed causes (T), the v1 table (K), the caps (P6), the request + record (P5a–c), the name rules (I) + the expected findings (R), from vflab measurements (`.scratch/u6/plan.md`, the D4 dumps); consultant-13 = its one bounded re-review (T2, I3, KT, C1, D open + K2 a new gap at the bound, fixed after it by MAIN; rulings: the full request key, raw declaring slots, per-handler qualification, the cap tie order, a `--child` step-fault seam).

Inputs: `.scratch/researcher-15/parse.md` (the parse API), `.scratch/researcher-16/inventory.md` (Lean 4.35.0's kinds, attributes, options + escape hatches), `.scratch/u6/plan.md` (measurements + design record), the residue dumps `fvdep-dev profile kinds|owned|positions|idents|stats|grammar|modules|scoped` (D4).

## Layers (each claim lives in one)

1. Proved (kernel; astra review before credit): the profile's contextual walk is exact against a spec over trees — acceptance + the first typed violation, every `choice` arm included (C); the header + name policy (I); the record reader + the attribution of a record to its request, the step's disposition + the outcome mapping (B2, B3, P5). B1's order = a claim on its caller's plan (U8's `check`, U7's admission: U2's effect plan runs the barrier before any compile, fill, roots check or view), realized for tests by D2.
2. Reviewed table + regressions (kernel data): each admitted structural role of the v1 table is safe, by review against researcher-16's lists + what the admitted forms dispatch to (K), + every refusal class has a planted module refused, named, with context, position, shape + budget controls (R).
3. Residue (named with its reason): the parse's fidelity — the tree the child checks = the tree the build elaborates (P) —; the child's process + file seams; the runtime behaviour of the trusted imports (`dbgTrace`, panics, Init/Std's `@[extern]`s). "Accepted ⇒ phase 1 runs toolchain + fvdep code alone" = layers 2 + 3 + B's premises (the build compiles the frozen bytes the child checked under the same recipe + toolchain), never a single theorem.

## P Parse + check (residue `lean-parser`; the checker inside = layer 1)

- P1 One bounded child process (`fvdep-parse`, an fvdep-owned executable beside `fvdep`, `supportInterpreter`: loading the toolchain's parser extensions runs their compiled code through the interpreter) run through U5's runner (bwrap, tmpfs, deadline `seconds`), because the parse path (Lean's parser + the tree conversion) is quadratic in nesting depth + uninterruptible (vflab, Lean 4.35, no output: parentheses 10,000 deep 0.93 s, 50,000 deep 20.5 s, 100,000 deep 80.2 s at 1.3 GB; S1's 1 MiB cap admits ≈ 4–5× deeper). It parses AND checks: the pure checker (C) runs in the child; only a record leaves (P5) — no tree crosses the boundary. A deadline passed, a signal or a malformed record = `infra io`, exit 2 (U5 P5's class). Layout (U6-C): `fvdep-parse` (beside the running executable; D's `--child` file in its place, same name) copied to `<run>/step/fvdep-parse` beside the step helper (bound at `/fvdep/step`), the request + the frozen batch at `/fvdep/src`, the sysroot at `/fvdep/sysroot` — no other bind; argv `--mkdir out --file-bytes <fileCap> -- /fvdep/step/fvdep-parse` (the child takes no argument: any = usage, exit 2), environment `LEAN_ABORT_ON_PANIC=1` alone (a toolchain panic = a signal = infrastructure, never a parse continued on a default value). Everything the child runs on uncapped `Syntax` is an explicit-stack loop: a left-nested chain such as `a ++ a ++ …` (built by the trailing-parser loop without recursion) is as deep as its length. Lean runs `main` on its own thread (`lean_run_main`: 1 GiB by default, sized by `LEAN_STACK_SIZE_KB`; `ulimit -s` binds only the initial thread), so a recursive traversal would pass at the production default; the loops keep the child's stack use independent of nesting: `lake test` holds a 20,000-term chain to `cap depth 4096` with the Lean stack at 256 KiB (the parse + converter pass at 64 KiB), where Lean 4.35's recursive `getPos?` (a cap's location) or `hasMissing` (the body check) crashes (mutants M24 + M25: killed).
- P2 Provenance: the child binds fvdep's own toolchain sysroot alone — no project, prior or library artifact, no inherited `LEAN_PATH`, no plugin; it never runs the frontend on candidate source.
- P3 Grammar per module: the trusted visible environment of THAT module's own import closure (its toolchain imports through every library + batch module it reaches, in the frontend's order + flags: `Init` implicit), importing the toolchain's modules alone (`importModules (loadExts := true)`); a sibling's `Std` never extends another module's grammar; the grammar = the ORDERED import list (import order can change the parse), cached per distinct list inside one child run. The list = `Init` first (implicit; an explicit `import Init` collapses into it), then each toolchain module (first component `Init`, `Std`, `Lean` or `Lake`) that a non-toolchain module of the closure imports, in the order a depth-first walk first meets it (each module's imports in source order, each module visited once), each listed once (pure: `FvdepCore.Profile.grammar`); `importModules` over it gives the toolchain modules the frontend's order (its depth-first post-order restricted to them) — U6-D's differential pins this (`allImportedModuleNames` filtered to toolchain modules, a fixture with a library hop). Options = the module's own recipe (`consumer/1` or `library/1`: `FvdepCore.Build`); `doc.verso` + `doc.verso.module` = Lean 4.35.0's default false in both recipes (`set_option` refused ⇒ off in parse + build; a toolchain bump requalifies). Example (vflab, `fvdep-dev profile owned` under `FVDEP_DEV_GRAMMAR`): `Std.Time`'s term notations are not scoped (`syntax "date(" str ")" : term` …), so `def f (date : String → Nat) := date("2024-01-01")` parses as `Std.Time.termDate(_)` (a token `date(`) under `[Init, Std]` + `[Init, Std.Time]`, and fails under `[Init]` (`1:35: unexpected token '('; expected command`: an application needs a space).
- P4 Scope (the fixed initial context is exact): S = the namespaces carrying scoped parser entries under `Init` + `Std` (pinned per toolchain; gate check: live S = pinned S). Every admitted import lies in `Std`'s or `Init`'s closure (vflab: all 493 `Std.*` + all 652 `Init.*` modules) and scoped entries only grow with imports ⇒ S over `[Init, Std]` ⊇ every module's own. Measured, 30: `Array`, `BitVec`, `Int`, `Lean`, `Lean.Order`, `Lean.Parser.Tactic`, `Lean.Parser.Tactic.Conv`, `Lean.Parser.Tactic.Grind`, `List`, `Rat`, `String.Internal`, `Vector` (12 under `Init`), `Std.DHashMap`, `Std.DHashMap.Internal.Raw`, `Std.DHashMap.Internal.Raw₀`, `Std.DHashMap.Raw`, `Std.DTreeMap`, `Std.DTreeMap.Internal.Impl`, `Std.DTreeMap.Raw`, `Std.Do`, `Std.HashMap`, `Std.HashMap.Raw`, `Std.HashSet`, `Std.HashSet.Raw`, `Std.Sat.AIG`, `Std.TreeMap`, `Std.TreeMap.Raw`, `Std.TreeSet`, `Std.TreeSet.Raw`, `Std.WP`. The walk refuses `namespace N` when an accumulated full name (the enclosing namespaces ++ each prefix of N, shortest first) ∈ S or N has a `_root_` component (`scope namespace <the first such name>` | `<N>`), + every name X of an `open X …` (`openSimple`, the one activating form K admits) when an element of S ends with X's components (a full-component suffix match ⊇ every resolution through enclosing namespaces + earlier opens) or X has a `_root_` component (Lean strips `_root_` before resolving a root namespace, then activates it) (`scope open <X>`); `open X (y)` (`openOnly`, non-activating) admitted on its own merits; every other scope-changing form is outside K (`in`, `openScoped`, `openHiding`, `openRenaming`, `set_option`, term-level `open`) ⇒ no command changes the grammar ⇒ each command parses in the initial context. `def List.foo` (no `namespace` command) is admitted: the command parses whole before its declaration's temporary namespace exists. Evidence beyond the argument: a differential probe (the child's trees vs the frontend's pre-elaboration trees under the production recipes, incl. import + scope boundary fixtures).
- P5 Pass: the header first (`parseHeader`, empty environment: it still tokenizes candidate text, so inside the child); then per command in source order: `parseCommand` (monotone progress) → a parse failure — an error in the log, a recovered or `missing`-bearing tree, `eoi` before the input's end — refuses at the message's position (`parse <message>`: Lean's first error line without its `file:line:col: error:` prefix; without a logged error: no progress → `parse the parser made no progress` at the stuck position, a `missing` node → `parse a node is missing` at the command's start, `eoi` before the input's end → `parse the input continues after the end of the module` at that position) → the tree converted under P6's caps → walked (C). A pass = every command parsed, converted + walked clean, ending at the input's actual end. `#exit` + a body `import` = kinds outside K (Lean's loop stops there; the child walks them like any command: `kind Lean.Parser.Command.exit` | `kind Lean.Parser.Command.import` at their keyword). Bytes that are not UTF-8 = the module's header parse failure: `parse the source is not UTF-8` @ 1:0 (Lean's frontend refuses to read such a file). Observation (U6-C): the child observes in C1's order + stops at the batch's first event, read from the same pure functions it reports through (`headEvent` per header, `step` per command); `conclude` (pure, `FvdepCore.Profile.Batch`) judges the observations: `accepted` only when they name the request's modules in order, every header was observed with no event + every body met its input's actual end with no event (`concludeAccepts`) — an unobserved module or a stage stopped short is no outcome (the child exits nonzero → P5c).
- P5a Request (the supervisor writes `/fvdep/src/request.json`, the child reads it): the bytes = exactly U3 J's `print` of
  `{"library":[{"imports":[<M>…],"module":<M>}…],"limits":{"batchNodes":<n>,"depth":<n>,"nodes":<n>},"modules":[{"module":<M>,"path":<p>,"sha256":<hex>}…],"profile":"fvdep/profile/1","recipe":"consumer/1"|"library/1","role":"consumer"|"library","schema":1,"toolchain":<fingerprint>}` —
  `modules` = the batch in batch order with S1's frozen digests + each file's path relative to the snapshot root (`A.B` → `A/B.lean`, S2's spelling; the child refuses to proceed, exit ≠ 0, when a file it reads differs: `infra io`), `library` = one row per module of the pinned snapshot (consumer role; `[]` for the library role), ascending by module name in UTF-8 byte order, its `imports` = the explicit header imports in source order as U5 K's header observation reads them (the implicit `Init` never listed), `toolchain` = T1's fingerprint. The request = every input the child's verdict depends on beside the frozen sources + the sysroot it binds. The child reads it canonical-only (`readRequest`, claims `requestRead` + `requestExact`): a request outside this form — another JSON spelling, a list out of order or repeating a module, a path that is not its module's file, a recipe other than the role's, a limit 0 — is refused (exit ≠ 0 → P5c).
- P5b Record (one batch = one record; the child writes `/fvdep/work/out/results.json`, U5 R8 frames it): the bytes = exactly U3 J's `print` of
  `{"modules":[{"grammar":[<M>…],"module":<M>,"sha256":<hex>}…],"outcome":<O>,"profile":<s>,"recipe":<s>,"request":<hex>,"schema":1}` (canonical: sorted unique keys, no whitespace, no trailing LF; `profile` + `recipe` = strings the child copies from its compiled profile id + the request, compared at intake, never schema literals) —
  `request` = lowercase hex SHA-256 of the request bytes the child read, `modules` = the request's modules in batch order (C1), `sha256` = lowercase hex of the bytes the child read, `grammar` = P3's computed ordered list for every batch module once the header stage passed (all are computed before any body pass, B1, walked or not), `[]` for every module when the header stage refused; `<O>` = `{"kind":"accepted"}` | `{"cause":{"detail":[<s>…],"rule":<rule>},"column":<n>,"kind":"refused","line":<n>,"module":<M>}` (T; `line` ≥ 1, `column` ≥ 0) | `{"kind":"over","limit":"batchNodes"}` (P6).
  Supervisor intake (the proved reader, then the binding; first failure named, each reason checked over every module before the next — all names, then all digests —, `infra io: profile, the result record <reason>`; claims `recordRead`, `recordExact`, `intakeExact`): not exactly a `print`ed value of that schema (a field missing, extra or mistyped, an unknown rule or limit, a detail of the wrong arity for its rule, `line` 0) → `is malformed`; `profile` ≠ the supervisor's → `names profile <p>`; `request` ≠ the SHA-256 of the supervisor's request bytes → `names request <hex>, expected <hex'>`; `recipe` ≠ the request's → `names recipe <r>`; module count ≠ the request's → `lists <n> modules, expected <m>`; the i-th name ≠ the request's i-th (1-based) → `lists <M> at <i>, expected <M'>`; a digest ≠ S1's for that module → `has digest <hex> for <M>, expected <hex'>`; a refusal naming a module outside the batch → `refuses <M>, outside the batch`. The supervisor recomputes no grammar (it judges no consumer header before the barrier) ⇒ `grammar` = the child's report, shape-checked (plain module names), recorded, never judged. A detail string over 1,024 bytes (T's cap: the child cuts first) → `is malformed`.
  Binding reason (replaces a per-module grammar key, consultant-12 T-2; consultant-13: the batch alone left the library + toolchain unbound): the `request` digest binds every input the verdict depends on (P5a) ⇒ a record produced for another library snapshot, toolchain, batch, recipe or limit set fails intake by construction, with no premise about which process wrote it; no profile result is reused across commands in v1 (each check reruns the barrier: ≈ 1 s per ordinary batch), and U7's receipt binds the same inputs (implementation sources, library snapshot, verification profile ⊇ the profile id); the per-module names + digests stay checked for attribution + presentation.
- P5c Step disposition (in this order, each `infra io: profile, <detail>` unless named; a line's code = interface §6's, the observation names `toolMissing` + `sandboxSetup` print `tool_missing` + `sandbox_setup` like every `infra <code>` line): T1 → `infra tool_missing: …`; R6 `setupFailed`/`protocol` → `infra sandbox_setup: profile, <bwrap's line>` (`protocol`: `the step reported two exit codes`); `timedOut` → `the parse step timed out after <n> s`; the frame over `frameBytes` → `the parse step's frame passed frameBytes <n>`; an invalid frame (a status the helper's exit code contradicts included: it is not the child's) → `the parse step's frame is invalid`; the child `signaled n` → `the parse step died by signal <n>` (the child's status is read from a valid frame alone, so the frame cases precede it); the child never started → `the parse step did not start: <reason>`; a size cap hit (a tmpfs full at the helper's sample) → `the parse step exceeded a size cap`; the child `exited c`, c ≠ 0 → `the parse step exited with code <c>`; no `results.json` in the frame → `the parse step wrote no result record`; another file in it → `the parse step wrote <path> beside the result record` (the least path by bytes); then P5b's intake (pure: `disposition`, `verdictOf`, `judge` in `FvdepCore.Profile.Barrier`; `judgeAccepts`). Exit 0 + exactly `results.json` = the only way to a verdict.
- P6 Limits (`ProfileLimits`, typed, each ≥ 1; checked by the child while converting each command — iteratively, before the walk recurses —, `seconds` by U5's runner; D's `--limit <name>=<n>` overrides):
  - `depth` = 4,096: occurrences (every node, atom, identifier, `missing`) on the path from a command's root (depth 1; the header = a command) to the deepest occurrence; passing it refuses the module: `cap depth <n>` at the first occurrence past it in pre-order. Reason: every measured shape stops elaborating by syntax depth 518 under `consumer/1` (vflab: nested parentheses + `let` chains compile at 262–263, fail at 518–519 with `maximum recursion depth`; `if` chains fail from 134; `++` chains compile at 262, fail at 518 on a deterministic heartbeat budget) ⇒ 4,096 = 8× that headroom (chosen, not a proof for every shape); the corpus peaks at 31. Ties at one occurrence: `batchNodes` (infrastructure) before `depth` before `nodes`.
  - `nodes` = 4,194,304 (2^22): occurrences per module (header + every command); past it: `cap nodes <n>` at the first occurrence past it. Reason: the densest measured input = 3.0 occurrences per byte (nested parentheses), ordinary code ≤ 1.2 (`++` chains; corpus ≤ 0.49) ⇒ every file S1 admits (≤ 1 MiB) at density ≤ 4 fits.
  - `batchNodes` = 16,777,216 (2^24): occurrences per batch; past it the child stops + writes `{"kind":"over","limit":"batchNodes"}` → `infra io: profile, the batch passed batchNodes <n>`.
  - `seconds` = 120: the parse step's deadline; passed → `infra io: profile, the parse step timed out after <n> s`. Reason (vflab): `[Init, Std]` loads in ≈ 0.4 s; ordinary code parses at ≈ 0.9 MB/s (3.2 MB, 14,336 commands, 1.57 M occurrences: 3.5 s, 917 MB resident) ⇒ S1's whole 16 MiB snapshot cap ≈ 18 s for ordinary code; 120 s = a chosen deadline with that headroom, not a bound for every workload; a quadratic nesting (100,000-deep parentheses: 80 s) ends here.
  - The step's U5 T3 limits keep U5's defaults; D overrides `frameBytes` (the record's frame) + `fileBytes` (its file: a write past it ends the child by `SIGXFSZ`, as U5 measured for `lean` — measured for `fvdep-parse` at U6-C: `--limit fileBytes=64` → signal 25 — → `infra io: profile, the parse step died by signal <n>`). The batch's source bytes = S1's caps (1 MiB per file, 16 MiB per snapshot: `infra io` as U5).

## B Barrier + attribution (kernel; B2 + B3 proved, B1 = the caller's plan claim)

- B1 Order: freeze the source set (S1's snapshot) → every module's header policy (I) over the whole set → the per-module grammars (P3) → every module's body (P5) → only then any compile; a refusal, a malformed or mis-bound record, a batch cap, a deadline or a signal ⇒ no compile, no U5 K3 cache fill (cold library fills included), no library roots check, no view (U5 K's discovery of the library's headers = in-process reads before the barrier, allowed; U5's phase graph `FvdepIO.Phase.graph` parses the consumer headers in-process — no launch — only after an accepted barrier, for K2's plan); U7's candidate library likewise. Premise: the consumer role takes the pinned snapshot's library modules as admitted (U7 checked them under `library/1`); D's `--library` working copy is taken so (dev seam). The order is a property of the plan that calls the barrier: U8's `check` + U7's admission each state it as a claim on their effect plan (no shipped caller runs the barrier in U6); U6 ships the verdict (`judge`) + the dev seam realizing the order for tests (D2: tester-8's `phase.` cases, mutants B1–B3).
- B2 Attribution: a record counts only when its binding matches the request exactly (P5b); the build compiles the same frozen bytes; a reuse path never skips the applicable profile (`fvdep-dev phase check` raw builds without `--profile` + U5b oracle output are no acceptance evidence).
