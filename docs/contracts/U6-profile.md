# U6 — implementation profile v1 (contract; agent-read)

Requirement: Decisions "Conformance method" (2) — before any build, a trusted parse checks every implementation module against a positive allowlist over the whole tree (commands, terms, tactics, attributes, options); imports ⊆ Init, Std, the fvdep library + the manifest's implementation modules; reserved module prefixes refused; an unlisted kind ⇒ NOT PROVEN naming file:line + kind. Library admission (U7) runs the library's phase-1 modules (spec, model, registry) through the same profile. v1 freezes once the qualification corpus (Q) passes; each extension = a new version + requalification + regressions. Review history: consultant-12 rounds 1–2 (round 1: 1 accept, 8 amend, 1 reject; round 2: 3 closed, 5 open, 1 new gap — `_root_` opens, the grammar in the result key, ordered grammars, aggregate budgets, ties + cross-file order, role roots + declaration ownership, the rules in the freeze, the trace over result failures: fixed after the bound by MAIN; `.scratch/consultant-12/verdicts.md`), folded in here.

Inputs: `.scratch/researcher-15/parse.md` (the parse API), `.scratch/researcher-16/inventory.md` (Lean 4.35.0's kinds, attributes, options + escape hatches), `.scratch/u6/plan.md` (measurements + design record).

## Layers (each claim lives in one)

1. Proved (kernel; astra review before credit): the profile's contextual walk is exact against a spec over trees — acceptance + the first typed violation, every `choice` arm included (C); the header + name policy (I); the pure plan that orders the barrier, the attribution of each result to its exact inputs + the outcome mapping (B).
2. Reviewed table + regressions (kernel data): each admitted structural role of the v1 table is safe, by review against researcher-16's lists + what the admitted forms dispatch to (K), + every refusal class has a planted module refused, named, with context, position, shape + budget controls (R).
3. Residue (named with its reason): the parse's fidelity — the tree the child checks = the tree the build elaborates (P) —; the child's process + file seams; the runtime behaviour of the trusted imports (`dbgTrace`, panics, Init/Std's `@[extern]`s). "Accepted ⇒ phase 1 runs toolchain + fvdep code alone" = layers 2 + 3 + B's premises (the build compiles the frozen bytes the child checked under the same recipe + toolchain), never a single theorem.

## P Parse + check (residue `lean-parser`; the checker inside = layer 1)

- P1 One bounded child process (`fvdep-parse`, an fvdep-owned executable beside `fvdep`, `supportInterpreter`: loading the toolchain's parser extensions runs their compiled code through the interpreter) run through U5's runner (bwrap, tmpfs, deadline T `profileSeconds`), because the parse path (Lean's parser + the tree conversion) is quadratic in nesting depth + uninterruptible (vflab, Lean 4.35, no output: parentheses 10,000 deep 0.93 s, 50,000 deep 20.5 s, 100,000 deep 80.2 s at 1.3 GB; S1's 1 MiB cap admits ≈ 4–5× deeper). It parses AND checks: the pure checker (C) runs in the child; only a result leaves (P5) — no tree crosses the boundary. A deadline passed, a signal or a malformed result = `infra io`, exit 2 (U5 P5's class). Supersedes Decisions' "in-process" (amended: D).
- P2 Provenance: the child binds fvdep's own toolchain sysroot alone — no project, prior or library artifact, no inherited `LEAN_PATH`, no plugin; it never runs the frontend on candidate source.
- P3 Grammar per module: the trusted visible environment of THAT module's own import closure (its toolchain imports through every library + consumer module it reaches, in the frontend's order + flags: `Init` + `meta Init` implicit), importing the toolchain's modules alone (`importModules (loadExts := true)`); a sibling's `Std` never extends another module's grammar; the grammar = the ORDERED import list with its flags (never a set: import order can change the parse), cached per distinct list. Options = the module's own recipe's pinned list (`consumer/1` or `library/1`: `FvdepCore.Build`), with `doc.verso` + `doc.verso.module` off.
- P4 Scope (the fixed initial context is exact): S = the namespaces carrying scoped parser entries under `Init` + all of `Std` (scoped entries only grow with imports ⇒ a superset of every module's own), read from the live environment + pinned per toolchain (gate check: live S = pinned S; measured: 30 — 12 already under `Init` alone: `Int`, `List`, `Array`, `Lean`, `Lean.Order`, `Lean.Parser.Tactic(.Grind, .Conv)`, `Vector`, `Rat`, `BitVec`, `String.Internal`), used for every module. The walk refuses `namespace N` when an accumulated full name (the enclosing namespaces ++ each prefix of N) ∈ S, + every activating `open X` form (`open X`, `open X in`, `open scoped X`, `hiding`/`renaming`) when an element of S ends with X's components (a full-component suffix match ⊇ every resolution through enclosing namespaces + earlier opens); a `_root_` component in a `namespace` or an activating `open` name refused (Lean strips `_root_` before resolving a root namespace + then activates it, so a raw suffix match would miss `open _root_.Array`); `open X (y)` (`openOnly`, non-activating) admitted on its own merits; `set_option … in` refused ⇒ no command changes the grammar ⇒ each command parses in the initial context. Evidence beyond the argument: a differential probe (the child's trees vs the frontend's pre-elaboration trees under the production recipes, incl. import + scope boundary fixtures).
- P5 Pass + result: per module, `parseHeader` (empty environment; it still tokenizes candidate text, so inside the bounded child), then one `parseCommand` per command with monotone progress; a pass = a clean, non-recovering log, no `missing` descendant, the actual end-of-input (`#exit` refused even last; a body `import` refused). Result per module = accept | the first typed refusal, bound to (module name, source digest, its effective grammar = the toolchain module set of its closure in order + flags, recipe id, toolchain fingerprint, profile id) — unchanged bytes under a changed closure get a new grammar ⇒ a new key —, one H2-framed record (U5 R8), the batch's records = exactly the expected set (one per requested module, no extra, no missing); the supervisor's reader = a proved decoder of that record (the J/D pattern).
- P6 Bounds (T's limits, defaults from the corpus' maxima × a margin at U6-B): per module a tree depth cap `profileDepth` + nodes `profileNodes`; per batch the total source bytes `profileBytes` (≤ S1's `totalBytes`), total nodes `profileBatchNodes` + the record set's framed bytes (U5 R8's frame cap); checked by the child while converting (iteratively) before the walk recurses, the record set by the supervisor's reader; past one = a refusal naming it (a per-module cap) or `infra io` (a batch cap).

## B Barrier + attribution (kernel; proved pure plan)

- B1 Order: freeze the source set (S1's snapshot) → every module's header policy (I) over the whole set → the per-module grammars (P3) → every module's body (P5) → only then any compile; a refusal ⇒ no compile, no U5 K3 cache fill (cold library fills included), no artifact load; U7's candidate library likewise.
- B2 Attribution: a result counts only for its exact key (P5: module, source digest, effective grammar, recipe, toolchain, profile) + only inside a response set that is exactly the request's; the build compiles the same frozen bytes; a reuse path never skips the applicable profile (`fvdep-dev phase check` raw builds + U5b oracle output are no acceptance evidence).
- B3 Outcome: a refusal → NOT PROVEN naming file:line + the typed cause (interface §3); infra → exit 2.

## K The v1 table (kernel data)

- K2 Atoms: keyword + punctuation atoms per role; literal kinds (`num`, `str`, `char`, `scientific`, `fieldIdx`, `name`) by a payload rule (the lexer already accepted the payload); plain docstrings in their exact doc-payload slot; `deriving` targets by name; tactic configs by exact shape (`omega` + `decide` with the empty config: `+native` refused); risky atoms refused by name (`noncomputable`/`public`/`meta`/`@[expose]` in `sectionHeader`, `noncomputable` in `deriving`).

## I Headers + names (kernel; proved)

- I1 Header, by role: an implementation module imports ⊆ {Init, Std.*, the pinned library's `Fvdep.*` modules as its snapshot lists them, the manifest's implementation modules}; a library phase-1 module imports ⊆ {Init, Std.*, the candidate library's own `Fvdep.*` phase-1 modules} (never `FvdepProofs`, never `FvdepPreview` from `Fvdep`: U4's direction rules); both: no `prelude`, no import modifier (`public`/`meta`/`all`: separate kinds).
- I2 Ownership: an implementation module's name + every declaration it introduces (each `namespace`'s accumulated name ++ each declared name) have a first component ∉ {Init, Std, Lean, Lake} ∪ `Fvdep*` (U2's reserved names: a module named like a spec module, or a declaration placed into `Fvdep.Base64…`, refused); a library module's declarations stay under `Fvdep`; linker symbols stay the compiler's (U9 qualifies the compiler-selected symbol, initializer + ABI).
- I3 Reserved components in SOURCE, every identifier leaf (a full name is built from leaves: `namespace Foo.bar` + `def _unsafe_rec` forges `Foo.bar._unsafe_rec` — U4's open `.agent/review.md` row): (a) names the compiler selects by name (`_unsafe_rec`, `_boxed`, `_impl`, `_override`, `_cstage<n>`, `_spec_<n>`, `_rarg`, `_closed`, `_lambda`, `_elambda`, `_private`, … fixed in U6-C from the toolchain's codegen sources) + (b) names Lean generates (`match_<n>`, `proof_<n>`, `eq_<n>`, `brecOn`, `below`, `casesOn`, `recOn`, `noConfusion`, `rec`, `ctorIdx`, …) + (c) `_root_` (a declaration `def _root_.Fvdep.Base64.x` inside `namespace Launch` would land in a reserved namespace past I2's prefix check) refused in every leaf, a use included (corpus: 1,826 leaves, 216 distinct components, none reserved); legitimate generated OUTPUT (a structural recursion's own `_unsafe_rec` companion) is the compiler's, never refused.
